# Diagnose and the first fix on real repositories (2026-11-19)

The v0.2 gate ([plan](../plans/phase2.md)) asks, on a real repository, for duplicate findings a
person agrees with and one automatic merge with all tests still passing. Nine well-known
pure-Python projects, shallow clones of their default branch on 2026-11-19.

## Duplicated logic found

| Project | Lines of Python | Groups | Exact / renamed / near | Lines to remove |
|---|---|---|---|---|
| sympy | 815k | 325 | 37 / 151 / 137 | 9,874 |
| sphinx | 148k | 89 | 19 / 46 / 24 | 4,576 |
| networkx | 208k | 42 | 3 / 14 / 25 | 1,771 |
| boltons | 26k | 19 | 12 / 1 / 6 | 449 |
| pyparsing | 52k | 13 | 7 / 3 / 3 | 445 |
| pygments | 137k | 13 | 2 / 4 / 7 | 326 |
| click, dateutil, more-itertools | 30k, 24k, 17k | 2, 1, 1 | | 36, 17, 13 |

A random 12 groups from sympy and sphinx, read side by side, were all real copies: sphinx's C and C++
parsers share an exact `_parse_cast_expression`, sympy's `SeqAdd.__new__` and `SeqMul.__new__` are
near copies, `merge_members_option` is copied into a legacy module. Some are deliberate patterns
(`Poly.add` / `Poly.mul`), and sphinx's JS stemmers are generated code: a duplicate nobody would
fix by hand. **Next improvement:** leave out generated files ("generated by", "do not edit").

boltons copies its whole `OrderedMultiDict` into `urlutils` on purpose (the file says so: each
module stands alone). The fix refuses it (methods); a fix that merged it would go against the
project's design, which is why merges need a person's or a project's agreement, not only tests.

## The first fix

Dry runs: 1 safe merge in all nine projects. The refusals were right:

| Project | Exact copies | Merged | Refused, by reason |
|---|---|---|---|
| sympy | 37 | 1 | 33 methods, 2 import cycles, 1 not the same tree |
| sphinx | 22 | 0 | 21 methods or not top-level, 1 globals that differ |
| pyparsing | 12 | 0 | example copies each using their own module's classes (globals differ), `global`, methods |
| boltons, networkx, pygments | 12, 3, 2 | 0 | methods; pygments' `regenerate` lives under `if __name__ == "__main__"` |

The merge: sympy's `printing/theanocode.dim_handling` is an exact copy of
`printing/aesaracode.dim_handling` (Aesara is Theano's fork). Applied in a copy, with sympy's
`printing` tests as the gate (`python -m pytest sympy/printing`, in a scratch virtualenv with
sympy's test dependencies; a local tag so a shallow clone can report its version):

- the tests pass before and after: 1,112 passed, 157 skipped, 9 expected failures;
- the change: `theanocode.py`, 45 lines removed, 1 import added;
- **the honest limit:** the 81 Theano and Aesara tests skip without those libraries, so no test
  exercised `dim_handling` itself. A direct check: `theanocode.dim_handling` is now the kept
  function, and returns the same on a sample call. Its docstring now says Aesara where it said
  Theano (the fix compares code, not docstrings).

So the gate is met in its letter (a merge on a real repository with its tests passing), with a
weak test of the function itself.

## What this says to do next

- **Methods** are by far the most common refusal (33 of 36 in sympy, 21 of 22 in sphinx). Merging
  copied methods needs a shared base class or mixin, a bigger change than an import.
- **Generated code** should be left out of duplicated logic.
